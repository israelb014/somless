# סומלס (SomLess)

כלי משפחתי לבדיקה מהירה: **האם המוצר הזה מכיל שומשום?**
נבנה עבור תינוק עם רגישות לשומשום — הורה עומד בסופר, מקליד שם מוצר, ומקבל
תשובה חד-משמעית תוך שנייה.

ארבעה מצבי תשובה:

| מצב | צבע | משמעות |
| --- | --- | --- |
| מכיל שומשום | אדום `#EF4444` | לא לתת |
| עלול להכיל | ענבר `#F59E0B` | ייצור משותף / רכיב לא ברור |
| נבדק ובטוח | ירוק `#22C55E` | נבדק מול התווית |
| לא במאגר | אפור | בדקו את התווית + כפתור הוספה מהירה |

> **כלי עזר בלבד — תמיד לבדוק את רשימת הרכיבים על האריזה. מתכונים משתנים.**

## איך זה בנוי

אתר סטטי לגמרי. **אין שרת, אין מסד נתונים, אין התחברות ואין חשבונות.**

- **Frontend:** Vite + React, עברית, RTL מלא
- **המאגר:** קובץ `data/products.json` בריפו — נטען כקובץ סטטי ונשמר בקאש של
  ה-service worker, כך שהאפליקציה עובדת בסופר גם ללא קליטה
- **הוספות מהטלפון:** נשמרות ב-IndexedDB על המכשיר עצמו, מסומנות בתוצאות
  בתג "מקומי", ולא עוזבות את הטלפון עד שמשתפים אותן
- **אחסון:** GitHub Pages, נפרס אוטומטית ב-GitHub Actions בכל push

## שפה עיצובית — "על טהרת השומשום"

רקע חום-שחור עמוק עם radial glow זהוב, משטחי טחינה קרמיים לכרטיסים, והדגשות
זהב קלוי. **צבעי הסטטוס לא משתנים לעולם** — אדום `#EF4444`, ענבר `#F59E0B`
וירוק `#22C55E` מוצגים תמיד על משטח שמבטיח להם ניגודיות: דיסק כהה מתחת
לטבעות, ומילוי מלא עם דיו כהה (`#1F1409`) בתגיות. כל צמד טקסט/רקע נבדק
לניגודיות AA — הזוג הצמוד ביותר הוא הדיו על האדום, 4.8:1.

כל שומשום באפליקציה נגזר מרכיב אחד, `SesameSeed`, ומגיאומטריה משותפת
ב-`src/lib/seedShape.js` — אותו נתיב משמש את ה-SVG, את הפרטיקלים בקנבס
ואת מחולל האייקונים. אין אימוג'י ואין CDN.

### אנימציות

מטר שומשומים במעברי מסך, זרעים שמתעופפים בהקלדה, burst בלחיצה, טבעת סטטוס
שנבנית מזרעים אחד-אחד, ספינר וערימות איור. הכול על **קנבס יחיד** עם pooling
של אובייקטים; ה-requestAnimationFrame נעצר לגמרי כשאין פרטיקלים (נמדד: אפס
קריאות rAF ואפס פיקסלים מצוירים בסרק), והקנבס הוא `pointer-events: none` ולכן
לא חוסם לחיצות. החיפוש אף פעם לא ממתין לאנימציה.

נוספו גם: כותרת שנפתחת מזרע שנבקע (פעם אחת ב-session), ספירה מ-0 במספרי
הטאבים, ו-parallax עדין על זרעי הרקע בגלילה — transform בלבד, בלי reflow.

`prefers-reduced-motion` מכבה את כל הפרטיקלים ומשאיר fade-ים עדינים בלבד.
בנוסף יש מתג **"אנימציות שומשום"** בראש המסך, שנשמר ב-IndexedDB (ברירת מחדל:
דלוק).

### היררכיית תוצאות

ההתאמה הטובה ביותר מוצגת ככרטיס **hero**: טבעת 72px שנבנית מזרעים, שם בטיפוגרפיה
גדולה, תג סטטוס בולט ונגיעת gradient בגוון הסטטוס. שאר התוצאות הן שורות
קומפקטיות עם טבעת סטטית. גוף הכרטיס מציג שם, מותג, תג ואייקון בלבד — ההערה,
מקור הרשומה והפעולות (עריכה/מחיקה להוספות מקומיות) נפתחים ממגירת ה-i.

### שתי ערכות נושא

כהה (ברירת מחדל) ו**טחינה בהירה**, עם מתג שמש/ירח בכותרת. ברירת המחדל נגזרת
מ-`prefers-color-scheme` והבחירה נשמרת ב-IndexedDB; תג ה-`theme-color` מתעדכן
דינמית (ה-manifest עצמו סטטי ולכן לא יכול להתחלף). צבעי הסטטוס והדיסק הכהה
מתחת לטבעות זהים בשתי הערכות, וכל צמד טקסט/רקע נבדק ל-AA בשתיהן.

## הרצה מקומית

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # בנייה לפרודקשן → dist/
npm run preview  # תצוגה מקומית של הבנייה
npm run icons    # יצירה מחדש של אייקוני ה-PWA
```

ה-service worker נרשם רק בבנייה לפרודקשן, כדי לא להפריע ל-hot reload בפיתוח.

## התקנה בטלפון

פתחו את כתובת האתר ב-Chrome / Safari → **הוספה למסך הבית**. האפליקציה נפתחת
במסך מלא, נטענת מיידית, ועובדת גם ללא רשת.

## עדכון המאגר: שולחים הודעה לקלוד קוד

המאגר המרכזי הוא קובץ בריפו, ולכן עדכון שלו הוא commit. התהליך:

1. בטלפון — מוסיפים מוצרים דרך כפתור **הוספה**. כל הוספה נשמרת על המכשיר
   ומופיעה בתוצאות עם התג "מקומי".
2. במסך **שלי** — לוחצים **שיתוף**. הכפתור משתמש ב-Web Share API (ובנפילה,
   מעתיק ללוח) ומייצא את ההוספות כ-JSON.
3. שולחים את ה-JSON בהודעה ל-Claude Code עם הבקשה:
   **"מזג את ההוספות לתוך data/products.json"**.
4. Claude מריץ את המיזוג, דוחף לריפו, ו-GitHub Actions פורס אוטומטית. תוך
   דקה-שתיים כל מי שפותח את האתר מקבל את המאגר המעודכן.

המיזוג עצמו:

```bash
npm run merge -- additions.json     # או:  cat additions.json | npm run merge
```

הסקריפט מזהה כפילויות לפי שם מנורמל (מוצר קיים מתעדכן, חדש נוסף), מעלה את
`version` ומעדכן את `updatedAt`.

## מבנה הנתונים

`data/products.json` — מקור האמת היחיד של המאגר:

```json
{
  "version": 1,
  "updatedAt": "2026-08-20",
  "allergen": "sesame",
  "products": [
    {
      "id": "p001",
      "name": "טחינה גולמית",
      "brand": "",
      "allergens": { "sesame": "contains" },
      "note": "רשומת פתיחה — יש לאמת מול התווית",
      "barcodes": [],
      "source": "seed"
    }
  ]
}
```

- `allergens` היא מפה ולא שדה בודד — המודל מוכן לריבוי אלרגנים, גם אם ה-UI
  מציג רק את `ACTIVE_ALLERGEN` שמוגדר ב-`src/config.js`.
- `source`: `seed` (מאגר הפתיחה), `family` (מוזג מהוספות), `local` (הוספה
  שקיימת רק על מכשיר אחד).
- `barcodes` הוא שדה אופציונלי (`string[]`) — ברקודים ששויכו למוצר דרך
  הסריקה. הוא מצטבר במיזוג, כך ששיוך שנעשה בטלפון לא הולך לאיבוד.
- מאגר הפתיחה: 21 מוצרים **מכיל** ו-5 **עלול להכיל**, ברמת קטגוריה בלבד ללא
  מותגים, כל אחד עם ההערה "רשומת פתיחה — יש לאמת מול התווית".
- **הרשימה הלבנה (`safe`) מתחילה ריקה בכוונה** — מוצר מסומן כבטוח רק אחרי
  שנבדק מול התווית.

## פרטיות

הריפו והאתר לא מכילים שום פרט מזהה: אין מיילים, אין שמות, אין חשבונות ואין
טלמטריה. ההוספות שלכם נשמרות רק על הטלפון שלכם, ומגיעות לריפו רק אם בחרתם
לשתף אותן. האתר עצמו מכיל שמות מוצרים בלבד.

## חיפוש

- רץ מקומית על כל הקשה (המאגר קטן — אין קריאות רשת)
- נרמול עברית: הסרת ניקוד, המרת אותיות סופיות (ם→מ, ן→נ, ץ→צ, ף→פ, ך→כ),
  הסרת גרשיים ומקפים, lowercase לאנגלית
- סלחנות לשגיאות כתיב: התאמה חלקית + Levenshtein עד 2 על מילים באורך 4+
  (מימוש עצמי, ללא ספריות)
- מיון: התאמה מדויקת → מתחיל ב- → מכיל → fuzzy

## פריסה

האתר חי בכתובת **https://israelb014.github.io/somless/**

אוטומטית לחלוטין: כל push לענף ברירת המחדל מריץ את `.github/workflows/deploy.yml`,
שבונה עם ה-base path הנכון ודוחף את `dist/` לענף `gh-pages` — ומשם GitHub Pages
מגיש אותו. אין צעדים ידניים.

הפרסום נעשה בדחיפה לענף ולא דרך ה-Pages API בכוונה: ה-`GITHUB_TOKEN` של Actions
מקבל `Pages: write` אבל endpoint יצירת האתר מחזיר 403 בריפו הזה. דחיפה ל-`gh-pages`
דורשת רק `contents: write` ועובדת.

## סריקת ברקוד

טאב **סריקה** פותח את המצלמה האחורית. הזיהוי משתמש ב-`BarcodeDetector` המובנה
כשהוא קיים, ואחרת נופל ל-`zxing-wasm` שנטען **רק** בכניסה למסך הסריקה (הוא לא
נמצא ב-bundle הראשי, וה-wasm מוגש מהאתר עצמו — בלי CDN). פורמטים: EAN-13,
EAN-8, UPC-A, עם בדיקת ספרת ביקורת כדי לסנן קריאות שגויות.

סדר הזיהוי:

1. **המאגר שלנו** (מרכזי + מקומי) לפי ברקוד — עובד גם בלי רשת.
2. **Open Food Facts** עם timeout של 4 שניות. מנותחים `allergens_tags`,
   `traces_tags` ו-`ingredients_text` בכל השפות שהוחזרו, מול רשימת מילים:
   שומשום, טחינה, סומסום, sesame, tahini, sésame, sesam, benne.
   אלרגן או רכיב → **מכיל**; traces → **עלול להכיל**; אחרת → *לא זוהה*.
   **מ-OFF לעולם לא מוחזר "בטוח"** — היעדר שומשום ברשימה אומר רק שלא זוהה.
3. **לא מזוהה** → מעבר להוספה ידנית כשהברקוד כבר משויך.

תוצאת OFF אפשר לשמור למאגר המקומי בלחיצה, ואם השם תואם (בחיפוש ה-fuzzy הקיים)
למוצר שכבר במאגר — מוצע לשייך אליו את הברקוד. כך המאגר המשפחתי לומד ברקודים.

**התראה:** "מכיל" ו"עלול להכיל" משתלטים על כל המסך בצבע הסטטוס, עם רטט
(`[200,100,200,100,400]` / `[200,100,200]`) וצליל Web Audio (בלי קובצי אודיו).
ה-`AudioContext` נפתח בלחיצה על טאב הסריקה, אחרת הדפדפן חוסם את הצליל. מתג
**"צליל ורטט בסריקה"** במסך "שלי" מכבה את שניהם. `prefers-reduced-motion` מכבה
את הפעימה בלבד — ההתראה עצמה נשארת.

בלי מצלמה (סירוב הרשאה או מכשיר לא נתמך) מוצגת הודעה עם מעבר לחיפוש הידני;
האפליקציה לא נשברת. המצלמה נעצרת לגמרי ביציאה מהמסך וגם כשהטאב יורד לרקע.

## מחוץ לסקופ

ללא OCR, ללא AI, ללא ריבוי אלרגנים ב-UI, ללא דיווחים קהילתיים, ללא התראות
push, ללא התחברות.
